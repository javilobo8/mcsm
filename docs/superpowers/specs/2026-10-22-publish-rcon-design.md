# Publish RCON per server — design

Date: 2026-10-22. Amends the main spec (`2026-10-12-mc-server-manager-design.md`), which said RCON "is never
published on the host".

## Intent

The administrator wants to reach a server's RCON from outside the panel (other machines on the LAN, and, at their
own choice, the internet) with any RCON client, using the password the panel already generates. mc-router cannot
route RCON (the Source RCON protocol carries no hostname), so each server that publishes RCON needs its own host
port, also when its game traffic enters through the router.

## Goals

- A per-server option, **off by default**: "Publish RCON". On = the container's 25575/tcp is published on a host
  port of the node.
- When turned on without a port, the panel assigns a free one from the node's port range (the same allocation the
  game port uses). The administrator can change it afterwards.
- The panel shows, for every server that publishes it, where RCON is: in the dashboard's server table and in the
  server's General section next to the RCON password.

## Non-goals

- Routing RCON through mc-router, or a TCP proxy of our own.
- Changing the RCON password from the UI (it stays generated by the panel).
- Encrypting RCON. The docs say it travels in clear text.

## Anti-goals

- Servers that do not turn it on must not change at all: same container, same `mcsm.spec_hash` (no recreation when
  the agent is updated). `TestHashGolden` stays untouched.
- No port collisions: a published RCON port counts as used everywhere a host port is checked or allocated
  (servers, extras, migrations towards the node, the node's router port).

## Decisions

### Spec

- New optional field `ports.rcon` (host port, TCP; integer 1–65535). **Absent = not published** (today's behaviour).
  Go: `Rcon int \`json:"rcon,omitempty"\`` in `spec.Ports`.
- Go and zod validate it the same way: range 1–65535, and it cannot equal `ports.game` nor the `host` of any extra
  port (any proto). Shared fixture `proto/fixtures/rcon-port-cases.json`, tested on both sides.
- Input (`specInputSchema` ports): `rcon` accepts a port or the literal `"auto"`. `completeSpec` resolves `"auto"` to
  `allocatePort` on the node (excluding the game port and the extras of the same spec). The stored spec only ever
  holds a number.
- Extra ports still cannot use container port 25575 (RCON is published only through `ports.rcon`). The properties
  `enable-rcon`/`rcon.port`/`rcon.password` and the `RCON_*` env stay reserved.
- Templates do not carry it: `templateSpecSchema` already has no `ports`.
- PATCH: `ports` is replaced as a whole section (first-level merge). Every client that sends `ports` must send
  `rcon` too, or it unpublishes it. The web form does.

### Agent

- `BuildContainer`: with `Ports.Rcon != 0`, expose `25575/tcp` and bind it to that host port. Absent adds nothing,
  so the hash only changes for servers that publish it. Starting goes through `startOrDiscard` as usual.

### Panel

- One shared helper lists a spec's host ports (game, extras, rcon) and replaces every hand-written
  `[game, ...extra.host]`: `ServersRepo.usedGamePorts`, `ServersService.checkPorts`, `MigrationsRepo.specPorts`,
  `migration/propose.ts`.
- Migration: if the server publishes RCON and its port is taken on the target (servers, extras, open migrations
  towards it, router port, or the game port chosen for the target), the RCON port is reassigned to the first free one
  of the range. The proposal says so (`rconPort`, `rconChanged`) and the dialog and the completion message show it.
- Import: a container that publishes 25575/tcp on the host is proposed with `ports.rcon` = that host port (no
  warning any more). A 25575/udp publication is still dropped with a warning.

### Web

- Network tab of the server form: a "Publish RCON" switch. On → a port field prefilled with the assigned port
  (sends `"auto"` until saved the first time, or the number the user typed). A one-line note: RCON is not encrypted;
  mc-router cannot route it.
- General section, next to "RCON password": "RCON address" = `<host>:<port>` with host = Settings → Connection
  address host (not the router hostname, and ignoring its external port, which is the game's). Without a configured
  host, just the port. Absent when not published.
- Dashboard server table: under the game address, a muted `RCON <host>:<port>` line for servers that publish it.
- `spec-diff.ts`: label for `ports.rcon` ("Published RCON port"; absent = "not published").

### Docs

- Main spec: amend the lines that say RCON is never published.
- Website (`servers.md`, `settings.md`, `security.md`) and README (same sentences): RCON is internal unless the
  server publishes it; how to turn it on; clear text; one port per server; it does not wake an asleep on-demand
  server.
- `CLAUDE.md` learned notes: `ports.rcon` and the shared host-port helper.
